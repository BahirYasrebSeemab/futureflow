# mflow P3a: API core (Worker, D1, auth, sync, day loop) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Create `apps/api`, a Cloudflare Worker (Hono + D1). It pairs the phone, authenticates it, and syncs the time ledger idempotently. It also stores plans and day types (bad, away and verdicts), records heartbeats, reading logs and math attempts, and serves `/today`. Every endpoint is tested against a real local D1.

**Architecture:** The layers run in one direction: **routes** (Hono, zod at the edge) → **`@mflow/core`** (pure rules: `mergeEvents`, `earn`, `lockPlan`, `declareBadDay`…) → **ports** (repository interfaces in `src/ports.ts`) → **D1 adapters** (`src/adapters/d1/*`). Only the adapters and `src/index.ts` touch Workers-only APIs, so the Node rewrite only has to replace the adapters. The clock, id generator and rate limiter are injected through `createApp(options)`, so tests control time.

**Tech Stack:** Cloudflare Workers, Hono 4, D1 (SQLite), wrangler 4, zod 4 via `@hono/zod-validator`, `uuid` (v7), Vitest 5 with `@cloudflare/vitest-plugin` (tests run inside `workerd` with a local D1) and `@vitest/coverage-istanbul`.

**Spec:** `docs/superpowers/specs/2026-10-08-mflow-v1-design.md` (§4.3, §6, §11, §12, §13 and §14 apply).

**Scope split (P3 is three plans, like P2):**

- **P3a (this plan):** Worker, D1 schema, pairing and auth, rate limits, error envelope, ledger sync, plans (get, put, lock), day types, heartbeat, reading log, math attempts, `/today`.
- **P3b:** `packages/ai` (`talk()`/`judge()` router, Gemini and Jev adapters, budget guard), plus `POST /plans/:date/propose`.
- **P3c:** onboarding endpoints, the GitHub and reading verifiers, coach chat and memory, `GET /math/bank`, and cron (hourly and weekly).

## Global Constraints

- Bun for installs and scripts. One-off binaries run with `bun x <tool>`, never `bunx`, `npx` or pnpm. Run package scripts with `bun run --cwd apps/api <script>`.
- TypeScript `^6` (TS 7 breaks typescript-eslint), strict, `noUncheckedIndexedAccess`. ESM only.
- Vitest `^5.0.3` everywhere. The API uses `@cloudflare/vitest-plugin` (the renamed `@cloudflare/vitest-pool-workers`; it supports Vitest 5) and `@vitest/coverage-istanbul`, because V8 coverage doesn't work inside `workerd`.
- `compatibility_date` is `"2026-10-01"`. The bundled `workerd` 1.20261006 supports it. The spike showed that dates newer than the bundled runtime fail to start.
- Envelope on every response: `{ ok: true, data, error: null }` or `{ ok: false, data: null, error: { code, message } }`. Error messages never echo submitted values and never contain SQL, stack traces or internal names.
- zod only at the edges: request bodies, query, params and JSON read back from D1. Schemas live in `@mflow/contracts`, except one-line param objects.
- Device tokens: 32 random bytes, base64url (43 characters). **Only the SHA-256 hash is stored.** Sent as `Authorization: Bearer <token>`.
- Secrets (`SETUP_CODE`) only in Worker secrets or `.dev.vars` (gitignored). The repo ships `.dev.vars.example` only.
- Logs are structured JSON with **no personal data**: no summaries, places, reasons, task titles or tokens.
- D1: at most 100 bound parameters per statement, so bulk writes pass **one JSON parameter** and use `json_each`.
- All amounts are integer seconds. The day key comes from `dayKeyFor(now, device.utcOffsetMinutes, DEFAULT_RULES.dayBoundaryHour)`.
- Coverage thresholds for `apps/api`: lines, functions and statements ≥ 90, branches ≥ 85.
- Commits use the conventional format under the owner's git identity. **Never add `Co-Authored-By` or any AI attribution.** `learning/` is never committed.

## Review Focus

1. **The phone and the server both write "the same" grant** (base grant for a day, or a reward for the same task), plus a repayment tied to the duplicate reward, inside a 500-event batch. Expected: the grant is kept once, the orphan repayment is dropped and nothing is paid twice. Pinned in Task 4.
2. **A request retried after a network timeout:** a reused pairing code, a resent reading log or resent math attempts. Expected: no second device, no double rows, and a clear "already done" answer. Pinned in Tasks 3 and 8.
3. **A device in Dushanbe (UTC+5) at 03:59 vs 04:00 local.** Expected: "today" switches exactly at the 04:00 boundary for plan editing, bad days and the base grant. Pinned in Tasks 6, 7 and 9.
4. **A server or database failure, or malformed or oversized input.** Expected: a 4xx/5xx envelope that leaks no SQL, table names or submitted text, and a log line without personal data. Pinned in Task 5.
5. **Missing, malformed, unknown or revoked tokens.** Expected: 401 before any data is read or written. A rate-limited device gets 429. Pinned in Task 3.

```ts
import { env } from 'cloudflare:test';
import { createApp, type AppOptions } from '../src/app';

/** 2026-10-09 12:00 UTC, a Friday. */
export const T0 = Date.UTC(2026, 9, 9, 12, 0, 0);
/** Same value as SETUP_CODE in vitest.config.ts. */
export const TEST_SETUP_CODE = 'test-setup-code-0123456789';

export type Clock = { now: number };
export type Envelope<T> = {
  ok: boolean;
  data: T;
  error: { code: string; message: string } | null;
};
export type Reply<T> = { status: number; body: Envelope<T> };
export type App = ReturnType<typeof createApp>;

export const makeApp = (clock: Clock = { now: T0 }, options: AppOptions = {}): App =>
  createApp({ now: () => clock.now, ...options });

export type CallOptions = Readonly<{
  body?: unknown;
  raw?: string;
  token?: string;
  headers?: Record<string, string>;
  env?: Partial<Cloudflare.Env>;
}>;

export async function call<T = unknown>(
  app: App,
  method: string,
  path: string,
  opts: CallOptions = {},
): Promise<Reply<T>> {
  const headers = new Headers(opts.headers);
  if (opts.token !== undefined) headers.set('authorization', `Bearer ${opts.token}`);
  const body = opts.raw ?? (opts.body === undefined ? undefined : JSON.stringify(opts.body));
  if (body !== undefined && !headers.has('content-type')) {
    headers.set('content-type', 'application/json');
  }
  const res = await app.request(path, { method, headers, body }, { ...env, ...opts.env });
  return { status: res.status, body: (await res.json()) as Envelope<T> };
}
```

```ts
import type { Context } from 'hono';
import type { ContentfulStatusCode } from 'hono/utils/http-status';

/** Every failure the API can answer with. Messages are fixed text: they never echo input. */
export const ERRORS = {
  invalid_request: [400, 'The request is invalid.'],
  unauthorized: [401, 'Missing or invalid device token.'],
  invalid_code: [401, 'The setup code is wrong.'],
  not_found: [404, 'Not found.'],
  code_used: [409, 'This setup code was already used.'],
  plan_locked: [409, 'The plan is locked and cannot change.'],
  already_declared: [409, 'This day already has a day type.'],
  bad_day_limit_reached: [409, "This week's bad day is already used."],
  payload_too_large: [413, 'The request body is too large.'],
  duplicate_task_id: [422, 'Two tasks share an id.'],
  too_few_tasks: [422, 'The plan needs more tasks before it can lock.'],
  too_many_tasks: [422, 'The plan has too many tasks to lock.'],
  day_out_of_range: [422, 'That day cannot be changed now.'],
  rate_limited: [429, 'Too many requests. Try again in a minute.'],
  internal: [500, 'Something went wrong on the server.'],
  pairing_disabled: [503, 'Pairing is not configured on the server.'],
} as const satisfies Record<string, readonly [ContentfulStatusCode, string]>;

export type ErrorCode = keyof typeof ERRORS;

export const ok = <T>(c: Context, data: T, status: ContentfulStatusCode = 200) =>
  c.json({ ok: true, data, error: null }, status);

export const fail = (c: Context, code: ErrorCode, message: string = ERRORS[code][1]) =>
  c.json({ ok: false, data: null, error: { code, message } }, ERRORS[code][0]);
```

```ts
import { zValidator } from '@hono/zod-validator';
import type { ValidationTargets } from 'hono';
import type { z } from 'zod';
import { fail } from './envelope';

type Issues = { issues: readonly { path: readonly PropertyKey[]; message: string }[] };

/** Paths and rule messages only: submitted values are never echoed back. */
const describeIssues = (error: Issues): string =>
  error.issues.map((i) => `${i.path.map(String).join('.') || '(root)'}: ${i.message}`).join('; ');

export const valid = <Target extends keyof ValidationTargets, Schema extends z.ZodType>(
  target: Target,
  schema: Schema,
) =>
  zValidator(target, schema, (result, c) => {
    if (!result.success) return fail(c, 'invalid_request', describeIssues(result.error));
  });
```

`apps/api/src/app.ts`:

```ts
import { Hono } from 'hono';
import { v7 as uuidv7 } from 'uuid';
import type { AppEnv } from './env';
import { fail, ok } from './http/envelope';

export type AppOptions = Readonly<{
  now?: () => number;
  newId?: () => string;
  limiter?: (key: string) => Promise<boolean>;
}>;

export function createApp(options: AppOptions = {}): Hono<AppEnv> {
  const now = options.now ?? (() => Date.now());
  const newId = options.newId ?? (() => uuidv7());
  const app = new Hono<AppEnv>();

  app.use('*', async (c, next) => {
    c.set('deps', { now, newId });
    await next();
  });

  const v1 = new Hono<AppEnv>();
  v1.get('/health', (c) => ok(c, { status: 'ok' }));
  app.route('/v1', v1);

  app.notFound((c) => fail(c, 'not_found'));
  return app;
}
```

```ts
const TOKEN_BYTES = 32;

const base64url = (bytes: Uint8Array): string =>
  btoa(String.fromCharCode(...bytes))
    .replaceAll('+', '-')
    .replaceAll('/', '_')
    .replace(/=+$/, '');

/** 32 random bytes as base64url (43 characters). The phone keeps it; the server keeps its hash. */
export const newToken = (): string =>
  base64url(crypto.getRandomValues(new Uint8Array(TOKEN_BYTES)));

export async function sha256Hex(text: string): Promise<string> {
  const digest = await crypto.subtle.digest('SHA-256', new TextEncoder().encode(text));
  return [...new Uint8Array(digest)].map((b) => b.toString(16).padStart(2, '0')).join('');
}

/** Compares every character, so the time taken does not reveal how much matched. */
export function constantTimeEqual(a: string, b: string): boolean {
  if (a.length !== b.length) return false;
  let diff = 0;
  for (let i = 0; i < a.length; i++) diff |= a.charCodeAt(i) ^ b.charCodeAt(i);
  return diff === 0;
}
```

```ts
  async pair(codeHash, device, tokenHash, at) {
    // One transaction: the device is inserted only while the code is unused, then the code is used.
    const [inserted] = await db.batch([
      db
        .prepare(
          `INSERT INTO devices (id, name, token_hash, utc_offset_minutes, created_at)
           SELECT ?1, ?2, ?3, ?4, ?5
           WHERE NOT EXISTS (SELECT 1 FROM used_setup_codes WHERE code_hash = ?6)`,

      db
```

```ts
const BEARER = /^Bearer ([A-Za-z0-9_-]{43})$/i;

/** Resolves `Authorization: Bearer <token>` to a paired, unrevoked device, or answers 401. */
export const requireDevice = createMiddleware<AppEnv>(async (c, next) => {
  const token = BEARER.exec(c.req.header('authorization') ?? '')?.[1];
  if (token === undefined) return fail(c, 'unauthorized');
  const device = await c.var.deps.repos.devices.findByTokenHash(await sha256Hex(token));
  if (device === null) return fail(c, 'unauthorized');
  c.set('device', device);
  await next();
```

```ts
import { Hono } from 'hono';
import { constantTimeEqual, newToken, sha256Hex } from '../auth/token';
import type { AppEnv } from '../env';
import { fail, ok } from '../http/envelope';
import { rateLimit } from '../http/rate-limit';
import { valid } from '../http/validate';

const MIN_SETUP_CODE_LENGTH = 16;

/** Public: trades the one-time setup code for a device token. */
export const pairRoutes = new Hono<AppEnv>().post(
  '/device/pair',
  rateLimit(() => 'pair'),
  valid('json', PairRequestSchema),
  async (c) => {
    const secret = c.env.SETUP_CODE;
    if (secret === undefined || secret.length < MIN_SETUP_CODE_LENGTH) {
      return fail(c, 'pairing_disabled');
    }
    const body = c.req.valid('json');
    const codeHash = await sha256Hex(body.code);
    if (!constantTimeEqual(codeHash, await sha256Hex(secret))) return fail(c, 'invalid_code');

    const { deps } = c.var;
    const device = {
      id: deps.newId(),
      name: body.deviceName,
      utcOffsetMinutes: body.utcOffsetMinutes,
    };
    const token = newToken();
    const paired = await deps.repos.devices.pair(
      codeHash,
      device,
      await sha256Hex(token),
      deps.now(),
    );
    if (!paired) return fail(c, 'code_used');
    return ok(c, { deviceId: device.id, token }, 201);
  },
);
```

```ts
import { semanticKey, type LedgerEvent } from '@mflow/core';
import type { LedgerRepo } from '../../ports';

type EventRow = {
  seq: number;
  id: string;
  day: string;
  at: number;
  kind: LedgerEvent['kind'];
  seconds: number;
  ref_id: string | null;
  reason: string | null;
};

const COLUMNS = 'seq, id, day, at, kind, seconds, ref_id, reason';

export const toEvent = (r: EventRow): LedgerEvent => ({
  id: r.id,
  day: r.day,
  at: r.at,
  kind: r.kind,
  seconds: r.seconds,
  ...(r.ref_id === null ? {} : { refId: r.ref_id }),
  ...(r.reason === null ? {} : { reason: r.reason }),
});

// D1 allows 100 bound parameters per statement, so bulk values travel as one JSON array.
export const d1Ledger = (db: D1Database): LedgerRepo => ({
  async findMatching(ids, keys) {
    const { results } = await db
      .prepare(
        `SELECT ${COLUMNS} FROM ledger_events
         WHERE id IN (SELECT value FROM json_each(?1))
            OR semantic_key IN (SELECT value FROM json_each(?2))
         ORDER BY seq`,
      )
      .bind(JSON.stringify(ids), JSON.stringify(keys))
      .all<EventRow>();
    return results.map(toEvent);
  },

  async insert(events, deviceId, receivedAt) {
    if (events.length === 0) return [];
    const rows = events.map((e) => ({ ...e, semanticKey: semanticKey(e) }));
    const { results } = await db
      .prepare(
        `INSERT OR IGNORE INTO ledger_events
           (id, day, at, kind, seconds, ref_id, reason, semantic_key, device_id, received_at)
         SELECT value->>'id', value->>'day', value->>'at', value->>'kind', value->>'seconds',
                value->>'refId', value->>'reason', value->>'semanticKey', ?2, ?3
         FROM json_each(?1)
         RETURNING id`,
      )
      .bind(JSON.stringify(rows), deviceId, receivedAt)
      .all<{ id: string }>();
    return results.map((r) => r.id);
  },

  async page(since, limit) {
    const { results } = await db
      .prepare(`SELECT ${COLUMNS} FROM ledger_events WHERE seq > ?1 ORDER BY seq LIMIT ?2`)
      .bind(since, limit)
      .all<EventRow>();
    return { events: results.map(toEvent), next: results.at(-1)?.seq ?? since };
  },
});
```

```ts
import { mergeEvents, semanticKey, type LedgerEvent } from '@mflow/core';
import type { LedgerRepo } from '../ports';

/**
 * Appends events with core's merge rules (same id or same business key = already there; a
 * repayment of a dropped reward is dropped too). The unique columns in D1 make a concurrent
 * duplicate a no-op. Returns the ids actually written.
 */
export async function appendEvents(
  repo: LedgerRepo,
  incoming: readonly LedgerEvent[],
  deviceId: string | null,
  receivedAt: number,
): Promise<string[]> {
  if (incoming.length === 0) return [];
  const keys = incoming.map(semanticKey).filter((k): k is string => k !== null);
  const existing = await repo.findMatching(
    incoming.map((e) => e.id),
    keys,
  );
  const { added } = mergeEvents(existing, incoming);
  return repo.insert(added, deviceId, receivedAt);
}
```

```ts
import { z } from 'zod';
import type { AwayWindow, DayEntry, DayRepo } from '../../ports';

type DayRow = {
  day: string;
  kind: DayRecord['kind'];
  away_window_id: string | null;
  place: string | null;
  kept_task_ids_json: string | null;
  verified: 'pending' | 'yes' | 'no' | 'unknown' | null;
  distance_km: number | null;
};

type WindowRow = {
  id: string;
  place: string;
  from_day: string;
  to_day: string;
  kept_task_ids_json: string;
};

const IdsSchema = z.array(z.string());
const parseIds = (json: string): string[] => IdsSchema.parse(JSON.parse(json));

const toRecord = (r: DayRow): DayRecord =>
  r.kind === 'away' && r.place !== null && r.kept_task_ids_json !== null && r.verified !== null
    ? {
        day: r.day,
        kind: 'away',
        away: { place: r.place, keptTaskIds: parseIds(r.kept_task_ids_json), verified: r.verified },
      }
    : { day: r.day, kind: r.kind === 'away' ? 'normal' : r.kind };

const toEntry = (r: DayRow): DayEntry => ({
  record: toRecord(r),
  ...(r.away_window_id === null ? {} : { windowId: r.away_window_id }),
  ...(r.distance_km === null ? {} : { distanceKm: r.distance_km }),
});

const COLUMNS = 'day, kind, away_window_id, place, kept_task_ids_json, verified, distance_km';

export const d1Days = (db: D1Database): DayRepo => ({
  async between(from, to) {
    const { results } = await db
      .prepare(`SELECT ${COLUMNS} FROM day_records WHERE day BETWEEN ?1 AND ?2 ORDER BY day`)
      .bind(from, to)
      .all<DayRow>();
    return results.map(toRecord);
  },

  async entry(day) {
    const row = await db
      .prepare(`SELECT ${COLUMNS} FROM day_records WHERE day = ?1`)
      .bind(day)
      .first<DayRow>();
    return row === null ? null : toEntry(row);
  },

  async save(entries, at, window) {
    const upsert = db.prepare(
      `INSERT INTO day_records (${COLUMNS}, updated_at) VALUES (?1, ?2, ?3, ?4, ?5, ?6, ?7, ?8)
       ON CONFLICT (day) DO UPDATE SET
         kind = excluded.kind, away_window_id = excluded.away_window_id, place = excluded.place,
         kept_task_ids_json = excluded.kept_task_ids_json, verified = excluded.verified,
         distance_km = excluded.distance_km, updated_at = excluded.updated_at`,
    );
    const statements = entries.map(({ record, windowId, distanceKm }) =>
      upsert.bind(
        record.day,
        record.kind,
        windowId ?? null,
        record.away?.place ?? null,
        record.away === undefined ? null : JSON.stringify(record.away.keptTaskIds),
        record.away?.verified ?? null,
        distanceKm ?? null,
        at,
      ),
    );
    if (window !== undefined) {
      statements.unshift(
        db
          .prepare(
            `INSERT INTO away_windows (id, place, from_day, to_day, kept_task_ids_json, created_at)
             VALUES (?1, ?2, ?3, ?4, ?5, ?6)`,
          )
          .bind(
            window.id,
            window.place,
            window.from,
            window.to,
            JSON.stringify(window.keptTaskIds),
            at,
          ),
      );
    }
    await db.batch(statements);
  },

  async window(id) {
    const row = await db
      .prepare(
        'SELECT id, place, from_day, to_day, kept_task_ids_json FROM away_windows WHERE id = ?1',
      )
      .bind(id)
```

```ts
import { DEFAULT_RULES, earn, earnedSeconds } from '@mflow/core';
import { Hono } from 'hono';
import type { AppEnv } from '../env';
import { deviceToday } from '../http/day';
import { ok } from '../http/envelope';
import { appendEvents } from '../ledger/append';

export const todayRoutes = new Hono<AppEnv>().get('/today', async (c) => {
  const { deps, device } = c.var;
  const { ledger, plans, days } = deps.repos;
  const now = deps.now();
  const day = deviceToday(device, now);

  const [plan, entry, dayEvents, totals] = await Promise.all([
    plans.get(day),
    days.entry(day),
    ledger.forDay(day),
    ledger.totals(),
  ]);

  // "Paid at the day boundary, or on the first sync of the day" (spec §6.3). Idempotent:
  // core refuses a second grant, and the business key refuses a racing duplicate.
  const grant = earn(
    dayEvents,
    { kind: 'base_grant' },
    { day, at: now, newId: deps.newId },
    DEFAULT_RULES,
    { planLocked: plan?.status === 'locked', outstandingBorrow: totals.outstandingBorrow },
  );
  const written = grant.ok ? await appendEvents(ledger, grant.value, null, now) : [];
  const paid = grant.ok ? grant.value.filter((e) => written.includes(e.id)) : [];

  return ok(c, {
    day,
    serverTime: now,
    plan,
    dayRecord: entry?.record ?? null,
    balanceSeconds: totals.balance + paid.reduce((sum, e) => sum + e.seconds, 0),
    earnedTodaySeconds: earnedSeconds([...dayEvents, ...paid]),
  });
});
```

```markdown
# 0006. Cloudflare Worker API (Hono + D1)

- Status: accepted
- Date: 2026-10-09

## Context

The phone works offline and enforces the time ledger itself. The server is the source of truth that
several writers (phone now, cron and verifiers in P3c) sync with. It must cost $0/month, run reliable
cron on the free tier, and stay easy to port to Node later (the owner will rewrite it to learn Node).

- **Cloudflare Workers + Hono + D1.** Free plan: 100k requests/day, 10 ms CPU per request, 5 cron
  triggers, D1 with 5M row reads and 100k row writes per day.
- **Layers:** routes (Hono + zod at the edge) → `@mflow/core` (rules) → ports (`src/ports.ts`) →
  D1 adapters (`src/adapters/d1`). Only adapters and `src/index.ts` touch Workers APIs. A Node port
  replaces `adapters/d1` (e.g. with SQLite or Postgres) and serves the same Hono app with `@hono/node-server`.
- **Auth:** a one-time `SETUP_CODE` (a Worker secret) is traded for a device token (32 random bytes,
  base64url). Only the SHA-256 hash is stored. Pairing a new phone means rotating `SETUP_CODE`.
  The device row and the used code are written in one transaction, so a code pairs exactly once.
  Revocation sets `devices.revoked_at`.
- **Ledger sync:** the server reuses core's `mergeEvents` (same id or same business key = already
  stored; a repayment of a dropped reward is dropped). `ledger_events.id` and
  `ledger_events.semantic_key` are UNIQUE, so a racing duplicate is a no-op (`INSERT OR IGNORE`).
  Bulk values travel as one JSON parameter through `json_each`, because D1 allows 100 bound
  parameters per statement. Pulls page by a server sequence (`seq`), not by time, so clock skew
  can't hide events. Events stamped more than 5 minutes ahead are rejected.
- **"Today" is the device's day:** `dayKeyFor(now, device.utcOffsetMinutes, 04:00)`. The offset is
  set at pairing and refreshed by every heartbeat.
- **Base grant:** `GET /today` writes the day's `base_grant` if no writer has (spec §6.3). It is
  idempotent through core's `earn` and the business key.
- **Errors:** every response is the `{ ok, data, error }` envelope. Messages are fixed text (never
  input or SQL). Unhandled errors log one JSON line with the error name and route only.
- **Tests:** `@cloudflare/vitest-plugin` runs tests inside `workerd` against a real local D1 with the
  real migrations. Storage is shared within a test file, so `test/setup.ts` empties every table
  before each test. The clock, ids and rate limiter are injected through `createApp(options)`.

## Consequences

- The phone is trusted for the amounts it earns (single owner in v1). The server doesn't yet
  recompute caps for phone-written rewards. Recomputing caps on the server is a product-version task.
- `totals()` scans the whole ledger on each `/today`. That's fine for one owner for years (~20k
  rows/year); a daily balance snapshot is the fix if it ever matters.
- `compatibility_date` must not be newer than the `workerd` bundled with the test plugin.
- AI (`/plans/:date/propose`) is P3b. Verifiers, cron, coach and onboarding are P3c.
```
