# Future Flow P7: a UI the owner likes (dark mode, hierarchy, feedback) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** the owner's verdict on v1 was that the UI is flat and dark mode is broken. Fix both:

1. **Dark mode works everywhere.** The stack header, the screen background behind transitions and the status bar follow the palette. Today the header stays white in dark mode, because the stack never gets a navigation theme and falls back to React Navigation's light default.
2. **Hierarchy.**
   - Today leads with one hero card in the brand blue: time left, a bar for how much of today's time is left, and what was earned.
   - The six identical buttons become icon tiles.
   - Lists (More, the guard checklist) become grouped rows with icons, instead of a stack of bordered cards.
3. **Feedback.**
   - Every tappable element scales down slightly on press, with a spring, on the native driver.
   - Primary actions tick with a light haptic.
   - Passing a task gives a success haptic.
   - Bars animate to their value, and new sections fade in.
4. **One visual system.** It's the existing `src/theme.ts`, extended rather than replaced:
   - the brand blue from the new icon
   - soft accent surfaces and a success colour
   - a type ramp, radius steps, shadows, motion durations
   - a shared text field, so the nine hand-styled inputs match and show focus

**Architecture:**

- **`src/theme.ts`:** palette tokens (`accentSoft`, `success*`, `heroBg`, `heroText`, `heroMuted`, `track`), plus `type`, `radius`, `shadow` and `motion`. It also gains `navTheme(palette, dark)`, a pure function from the palette to a React Navigation theme, unit-tested.
- **`src/screens/root-stack.tsx`:**
  - wraps the stack in `ThemeProvider` from `expo-router/react-navigation`, with `navTheme`
  - `screenOptions`: header and content colours from the palette, no header shadow, a slide transition
  - `StatusBar` from `expo-status-bar` set to `auto`
- **Components** (`src/components/`):
  - `pressable-scale.tsx`: Animated spring scale and an optional haptic
  - `button.tsx` on top of it, with variants `primary`, `secondary` (tonal), `ghost`, an optional `icon`, and haptics on primary
  - `icon.tsx`: Material icons only (Android app; one family)
  - `progress-bar.tsx`: animated width
  - `fade-in.tsx`: an entrance animation
  - `list-row.tsx`: an icon, title, detail and trailing slot, or a chevron
  - `text-field.tsx`: a TextInput with focus colour
  - `haptics.ts` in `src/lib/`: `tap`, `success` and `warn`; never throws
- **Screens:**
  - Today: hero, tiles, task rows with status pills
  - More: grouped rows
  - Guard checklist: rows with done/to-do icons
  - Pair: brand mark and better spacing
  - Inputs everywhere: the shared text field

## Global Constraints

- **Every `testID` and visible label that tests or Maestro flows use stays the same.** The visuals change; the contracts don't.
- **No new animation library.** RN `Animated` with `useNativeDriver` (transform and opacity only). Reanimated isn't a direct dependency, and adding it means a babel and native change without a local build.
- **Machine limits as before:** one Jest file at a time. The emulator run gives the screenshots to check against, including one in dark mode.
- **Accessibility:**
  - touch targets ≥ 48 dp
  - icons are decorative (`accessibilityElementsHidden`) next to text, labelled when alone
  - colour is never the only signal (pills keep their words)
  - animations are skipped when the system has reduce motion on
- Bun only. No AI attribution.
